# 企业级 Agent 平台 M1 产品需求

## 1. 产品目标

企业级 Agent 平台面向企业员工。M1 需要让员工能够基于企业提供的标准模板，或企业 Hub 中已有的自定义 Agent 镜像，创建并使用一个长期运行的 Agent。

M1 同时交付 Agent 平台和独立的 Connection 系统。Agent 平台负责 Agent 的创建、权限、运行和使用体验；Connection 系统负责外部平台接入、账户鉴权和用户授权。

M1 上线后应形成以下闭环：

1. 员工可以申请创建 Agent，系统管理员通过审批控制服务器资源占用。
2. Agent Owner 可以配置共同 Owner、可用范围和使用渠道。
3. 获得权限的员工可以通过平台对话页、平台托管企微渠道或自定义 Agent 的自有交互入口使用 Agent。
4. 同一个 Agent 可以服务多人；平台入口中的不同用户会话和数据相互隔离。
5. 标准模板由平台持续升级，已有 Agent 自动获得更新。
6. Agent 可以在获得当前用户授权后，通过 Connection 使用外部平台能力。

### 1.1 依赖与边界

- 平台使用公司现有账户和组织体系，不维护独立用户目录。
- Owner 配置平台认可的 LLM Gateway 访问地址、访问凭证、模型和推理强度。模型供应商接入、路由、成本、预算、配额和故障切换由 LLM Gateway 负责。
- 自定义 Agent 只使用公司 Hub 中已有的镜像。镜像构建、签名和扫描沿用公司 Hub 的现有流程。
- M1 不提供统一的 Sandbox。标准模板和自定义 Agent 可以使用自身已有的执行工具；平台不规定这些工具在 Pod 内还是外部服务中运行。

## 2. 用户角色

M1 只设置三类角色。

### 2.1 员工

- 浏览并使用自己有权访问的 Agent。
- 提交 Agent 创建申请，并查看申请状态。
- 建立自己的 Connection，并决定是否授权给某个 Agent 使用。

### 2.2 Agent Owner

- Agent 创建者自动成为 Owner。
- 可以增加或移除共同 Owner；所有 Owner 权限相同。
- Agent 必须始终保留至少一名有效 Owner。创建者不是不可移除的特殊 Owner。
- 配置 Agent 的可用范围和使用渠道。
- 为标准模板配置模型清单及默认项。
- 为支持 Connection 的 Agent 选择可用的 Provider 和 Action。
- 为 Agent 配置环境变量和 Secret。
- 为自定义 Agent 选择新的镜像 Tag 并发起升级。
- 停止、重启 Agent，并重试创建失败的 Agent。

### 2.3 系统管理员

- 批准或驳回 Agent 创建申请。
- 停用 Agent 并撤销其运行资格。
- 代替 Owner 重试创建失败的 Agent。
- 在 Owner 账号被禁用或离职后增加、移除或替换 Owner。
- 查看平台操作审计。

## 3. Agent 运行方式

- 一个 Agent 对应一个长期存在的独立 Pod，不按用户或会话创建 Pod。
- 一个 Agent 可以授权给多人使用，不是创建者的个人专属实例。
- 同一个 Agent 被多人同时使用时，每位用户只能看到自己的消息和处理状态。消息提交后必须立即显示为已提交或处理中；Agent 暂时无法接收任务时，产品明确提示繁忙并允许重试，不能静默丢弃消息。
- M1 不承诺固定并发数量，也不提供实例池、自动休眠或平台统一任务队列。
- Agent 停止时释放计算资源，但保留平台配置、渠道绑定、会话历史和用户数据。
- Agent 被系统管理员停用后同样释放计算资源，并保留上述数据。
- M1 不支持删除 Agent，也不设置运行资格期限。

## 4. 标准模板

M1 首发四个标准模板。

| 模板 | 主要场景 | 平台对话页 | 平台托管企微 | 模型选择 | 附件与结果文件 | Connection |
| --- | --- | --- | --- | --- | --- | --- |
| Codex | 编程任务 | 支持 | 支持 | 支持 | 支持 | 支持 |
| Claude | 通用知识工作 | 支持 | 支持 | 支持 | 支持 | 支持 |
| OpenCode | 开源编程 Agent | 支持 | 支持 | 支持 | 支持 | 支持 |
| Pi | 可扩展 Agent 工作流 | 支持 | 支持 | 支持 | 支持 | 支持 |

标准模板由平台团队通过现有运维方式在公司 Hub 中登记、升级和停用。M1 不建设可视化模板管理后台。

模板升级后，基于该模板创建的所有 Agent 自动升级。Owner 不能锁定旧版本、延迟升级或自行回滚。升级和平台回滚保留 Agent 配置、渠道绑定、平台会话历史、平台数据和原 PVC，但不保证 Runtime 自有数据能够兼容旧版本。平台团队在回滚或降级前必须评估并提示该风险。

升级不影响使用时，产品不展示技术过程。升级期间暂时不能使用时，对话页展示“更新中”，历史保持只读；升级失败时展示“暂时不可用”，由平台团队恢复服务。产品不能在更新期间接收消息后静默丢弃。

## 5. 自定义 Agent

### 5.1 准入与部署

- M1 只接受公司 Hub 中已经存在的 Agent 镜像，不接收源码，不在平台内构建镜像，也不接受外部镜像地址。
- 公司 Hub 是自定义 Agent 的镜像来源边界。平台校验镜像存在且提交人有权访问，并在审批通过后的创建过程中验证 Runtime Manifest、健康检查和 5.3 的交互入口要求；这些验证不增加源码审查或镜像审批。
- 创建或升级自定义 Agent 时，平台固定当时实际对应的不可变镜像版本。同名 Tag 后续发生变化，不能改变已经创建的 Agent。
- 自定义 Agent 不需要登记为标准模板，也不增加镜像审批或源码审查。平台不根据 Base Image 或父镜像血缘推断最终能力。
- 自定义 Agent 使用平台预设的标准资源规格，Owner 不能选择或修改 CPU、内存、副本数和弹性策略。
- 自定义 Agent 仍需经过系统管理员的创建审批，审批只用于控制服务器资源占用。

### 5.2 Base Image

M1 在公司 Hub 提供一个可供自定义 Agent 继承的 Base Image，帮助开发者形成统一的 `FROM` 使用方式。

M1 的 Base Image 不要求预集成身份、消息、Connection 或其他平台能力。它只为开发者提供统一的父镜像。使用 Base Image 是推荐方式，不是部署前提，也不会成为新的准入或审批条件。Base Image 和镜像继承只描述构建关系，不是平台运行类型。

### 5.3 交互入口

自定义 Agent 创建时必须选择一种交互入口归属：

- **自有交互入口：** Agent 自己提供人机交互入口并负责协议、身份、会话、历史、附件、模型和使用体验。平台负责部署、生命周期、Hub/Digest、资源、环境变量、Secret 和基础安全；需要从平台进入时，可以使用平台提供的身份与可用范围校验入口。此类交互不进入平台会话和历史。
- **平台交互入口：** Agent 使用平台对话页和平台托管渠道。M1 的自定义 Agent 只通过 ACP 接入，并在审批通过、Workload 启动后的创建过程中完成核心兼容性验证。平台负责身份、会话、历史和渠道体验，实际可用的模型、附件、结果文件和 Connection 能力由接入验证结果决定。

选择平台交互入口但 Runtime Manifest 未声明受支持 ACP 的自定义 Agent，创建失败且不启动 Workload；健康检查或 ACP 核心探测失败时，创建结果同样为“创建失败”。平台不为其他未知协议增加专用接入。

### 5.4 模型、文件与 Connection

- 使用自有交互入口时，模型、文件和外部调用由自定义 Agent 自己负责，平台不展示或管理这些能力。
- 使用平台交互入口时，平台只展示接入验证确认支持的模型、附件和结果文件能力。
- Connection 是自定义 Agent 的可选能力。使用平台交互入口并声明支持 Connection 时，外部调用必须经过平台和 Connection 系统；Agent 不能获得原始凭证。
- 未声明 Connection 能力时，平台不展示 Connection 配置。自定义 Agent 在自有交互入口中自行发起的外部调用不由 Connection 管理。

### 5.5 环境变量与 Secret

- 每个标准模板只开放平台为该模板定义的受控环境变量和 Secret。Owner 只能配置其中明确开放的键；其他键在保存前被拒绝。
- 自定义 Agent 允许 Owner 配置任意环境变量和 Secret K/V，包括 Runtime 约定的标准变量和镜像自定义变量。
- `AGENT_INFRA_*` 是平台保留前缀，Owner 不能覆盖；该限制同时适用于标准模板和自定义 Agent。
- 标准模板的模型 Base URL、API Key、模型和推理强度以第 8 节的平台模型配置为准；同名的 Owner 环境变量或 Secret 不能覆盖该配置。
- 普通值可以回显和修改。Secret 加密保存、不回显且只能替换。
- 环境变量和 Secret 变更由平台安全注入 Agent，不要求重新审批。

### 5.6 升级与回滚

自定义 Agent 默认保持当前固定的镜像版本，不自动跟随 Hub 中 Tag 的变化。只有 Owner 明确选择或重新选择 Tag 并执行升级时，平台才解析新 Digest 并更新部署。同名 Tag 指向新 Digest 时可以提示 Owner，但不能自动切换。

升级和回滚保留平台管理的 Owner、可用范围、仍受新版本支持的渠道绑定、平台会话历史、平台数据和原 PVC。平台回滚镜像和 Workload 配置，不自动创建 PVC 快照，也不保证 Runtime 自有数据能够兼容旧版本；Owner 主动降级前必须看到该风险。

## 6. 创建与审批

### 6.1 创建申请

所有公司员工都可以提交申请。申请内容包括：

- Agent 名称和说明。
- Agent 来源：标准模板或公司 Hub 中的自定义 Agent 镜像。
- 自定义 Agent 的 Hub 镜像标识和交互入口归属。
- 共同 Owner。
- 可用范围。
- 标准模板的模型清单及默认项。
- Agent 支持 Connection 时允许使用的 Provider 和 Action。
- 环境变量和 Secret。

### 6.2 审批规则

- M1 只允许系统管理员审批。
- 审批通过前不创建 Pod。
- 审批页展示 Agent 使用的预设资源规格和预计资源占用。
- 系统管理员可以批准或驳回；驳回原因必填。
- 申请人可以修改原申请后重新提交，无需创建新申请。
- 申请人可以在待审批时撤回申请。撤回后不创建 Agent，原申请只作为历史记录保留；再次申请时需要提交新申请。
- Agent 获得运行资格后，停止、重启、模型、权限和渠道调整不需要重新审批。
- M1 不发送审批、创建成功或创建失败的邮件及企微通知，用户在 Web 查看状态。

### 6.3 管理状态

Agent 申请、列表和详情页只展示以下管理状态：

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| 待审批 | 申请等待系统管理员处理 | 修改申请、撤回申请 |
| 已撤回 | 申请人主动撤回，未创建 Agent | 查看历史记录 |
| 已驳回 | 申请未通过 | 查看原因、修改后重新提交 |
| 创建中 | 审批通过，正在创建 | 查看状态 |
| 可用 | Agent 已获得运行资格 | 停止、重启、配置、使用 |
| 已停止 | Owner 主动停止 | Owner 可以重启 |
| 创建失败 | 审批通过但创建未完成 | Owner 或系统管理员可以重试 |
| 已停用 | 系统管理员撤销运行资格 | Owner 不能恢复 |

创建失败后再次重试仍然失败，状态保持“创建失败”，并保留再次重试入口。已停止和已停用均不占用 Agent 计算资源。

### 6.4 服务可用性

管理状态为“可用”时，产品另外展示当前服务可用性：

| 服务可用性 | 用户看到的行为 | Owner 可执行操作 |
| --- | --- | --- |
| 正常 | 可以发送消息并获得回复 | 正常管理和使用 |
| 启动中 | 历史只读，暂时不能发送消息 | 查看状态 |
| 更新中 | 历史只读，暂时不能发送消息 | 查看说明 |
| 暂时不可用 | 展示失败原因和重试提示，历史只读 | 重启 |

Pod、进程和运行时名称等技术状态不在 M1 产品界面展示。

## 7. 权限与用户隔离

### 7.1 可用范围

- 平台不区分发现权和使用权，每个 Agent 只维护一套可用范围。
- 可用范围支持指定员工和公司组织。
- 用户只能发现和使用自己在可用范围内的 Agent。
- 创建者自动拥有 Agent，不需要重复加入可用范围。
- 普通使用者不能修改 Agent 的全局配置。
- 平台每次使用前都按当前公司账号状态和组织成员关系判断权限。权限来自公司组织时，员工调岗或退出该组织后立即失去由该组织获得的权限；直接指定给员工的权限只在该员工被移出可用范围后失效。
- 公司账号被禁用后，用户不能继续登录、使用 Agent、管理 Agent 或使用个人 Connection。平台停止仍可中止的处理中请求；已经提交给外部平台的操作不会自动撤回。

### 7.2 多用户隔离

同一个 Agent 被多人使用时，必须隔离每个用户的：

- 会话。
- 文件和附件。
- 个人记忆。
- 运行上下文。

标准模板和使用平台交互入口的自定义 Agent，由平台在每次交互时解析当前公司用户、Agent 和渠道权限，并要求 Runtime 隔离不同会话、文件、记忆和运行上下文。平台不规定各 Runtime 的进程或 Sandbox 实现方式。

使用自有交互入口的自定义 Agent 自己负责身份、权限和数据隔离；其交互不属于平台会话。通过平台提供的身份入口访问时，平台仍校验当前公司账号和 Agent 可用范围。

企微群聊中的消息对群成员共享可见，不适用“不同用户看不到同一群聊内容”的规则。群聊上下文只能使用当前群或线程内已经公开的消息；个人 Web 会话、个人附件、个人记忆和个人 Connection 不能进入群聊共享上下文。详细规则见 10.3。

## 8. 标准模板的模型配置

本章适用于四个标准模板。

Owner 配置的是平台认可的 LLM Gateway 访问选项。Agent 平台不负责模型供应商接入、模型路由、成本、预算和配额管理。

### 8.1 Owner 配置

- Owner 配置允许使用的模型清单。
- 每个选项包含平台认可的 Base URL、API Key、模型名和允许的推理强度。
- Base URL 只能从平台认可的地址中选择。
- API Key 加密保存且不回显，只能替换。
- 普通使用者看不到 Base URL 和 API Key。
- Owner 必须设置默认模型和默认推理强度。
- Owner 只配置一个选项时，相当于固定模型。

模型配置保存前必须验证 Base URL、API Key 和模型是否可用。该验证只确认连通性，不评价回答质量。

### 8.2 使用者选择

- 平台对话页的使用者可以从 Owner 配置的清单中选择模型和推理强度。
- 同一会话中可以切换，变更从下一条消息开始生效，不改变已有消息。
- 切换模型不要求新建会话。
- 企微入口始终使用 Owner 设置的默认模型和推理强度，不提供切换命令。
- Owner 删除会话当前使用的模型选项后，该会话从下一条消息开始切换到默认选项，并向使用者说明变化。
- API Key 失效、额度不足或模型不可用时，产品展示可理解的原因和稍后重试或联系 Owner 的入口，不向普通使用者展示 API Key。

Owner 保存配置后自动生效。底层如需重启 Pod，由平台处理，不向用户展示技术过程。

## 9. Connection 集成

Connection 是与 Agent 平台并行建设的独立系统。详细需求见 [Connection M1 产品需求](PRD-connection-M1.md)。

Agent 平台与 Connection 的边界如下：

- Connection 系统发布 Provider 和 Action，处理外部账户鉴权、凭证保管和 API 调用。
- Agent Owner 选择 Agent 可以使用的 Action，但不能绑定普通使用者的个人外部账号。
- 使用者将自己的 Connection，或自己有权使用的公司 Connection，授权给具体 Agent。
- Owner 新增 Action 后，已有 Connection 授权不能自动获得该新增能力。使用者确认更新后的能力范围后，Agent 才能代表该用户调用新增 Action。
- Owner 移除 Action，或 Connection 系统停用 Provider 或 Action 后，对应能力立即停止使用。
- Agent、模型和运行环境不能获得 Connection 保存的原始凭证。
- 四个标准模板必须完成 Connection 接入。
- M1 至少使用一个真实外部平台，完成连接、授权、调用和撤销授权的端到端闭环。

## 10. 使用渠道

### 10.1 统一身份

平台对话页和平台托管企微渠道统一映射到公司用户身份。Channel 层在每次使用前校验 Agent 可用范围，并把渠道会话映射为平台会话；Runtime 不重复维护用户白名单或渠道身份规则。

### 10.2 渠道绑定

- 平台对话页和平台托管企微渠道对四个标准模板始终可用。
- 使用平台交互入口的自定义 Agent 通过兼容性验证后，可以使用平台对话页和平台托管企微渠道。
- 每个支持平台托管企微渠道的 Agent 独立绑定自己的企微智能机器人或企微自建应用。
- 四个标准模板或通过兼容性验证、使用平台交互入口的自定义 Agent 创建成功后，Owner 可以按需绑定企微渠道；使用自有交互入口的自定义 Agent 不能绑定平台托管企微渠道。
- Owner 使用公司现有企微流程取得机器人或应用配置，平台只负责绑定和校验，不负责签发企微凭证。
- 平台不建设全公司统一的企微 Agent 入口。
- 渠道变更不需要重新审批，但必须记录操作。

### 10.3 企微会话

- 企微智能机器人支持单聊和群聊。
- 每条企微消息都必须映射到当前发送者的公司身份。无法映射身份，或发送者不在 Agent 可用范围内时，机器人不调用 Agent，并回复“暂无权限使用此 Agent”。
- 群消息和 Agent 回复对群成员可见。Agent 可用范围只决定谁能触发 Agent，不能阻止其他群成员阅读群内已有内容；Owner 绑定群聊时必须看到该提示。
- Channel 层按 Agent、渠道绑定、会话类型、群聊和线程生成稳定的会话映射。共享上下文只包含当前群或线程中已经公开的消息，不读取参与者的个人会话、个人附件或个人记忆；Runtime Adapter 不自行改变该映射。
- 群聊中调用 Connection 时，只能使用触发本次调用的消息发送者已经授权给该 Agent 的 Connection。其他群成员的 Connection 和授权不能被使用。
- Web、企微智能机器人和企微自建应用之间不合并会话。

## 11. Web 产品体验

### 11.1 页面

M1 提供以下页面：

- Agent 列表：展示当前用户有权使用的 Agent。
- Agent 详情：展示 Agent 说明、Owner、可用渠道、模型选择范围和所需 Connection 能力，并提供可用的使用入口。
- 对话页：提供 ChatGPT 式对话和个人历史会话。
- 我的 Agent：查看申请状态，管理自己作为 Owner 的 Agent。
- 创建与配置页：提交申请并管理 Owner、可用范围、模型、渠道和 Connection Action。
- 我的 Connection：进入独立 Connection 系统，管理个人 Connection 和 Agent 授权。
- 审批页：系统管理员审批申请和停用 Agent。
- 操作审计页：仅系统管理员可见，属于 M1 次要优先级。

自定义 Agent 的自有交互入口不属于平台对话页。平台可以在 Agent 详情中提供经过身份和权限校验的访问入口，但不接管其交互体验和历史。

### 11.2 对话能力

平台对话页支持：

- 新建会话和查看历史会话。
- 流式回复、停止回复和重新生成。
- 重新生成基于同一条用户消息产生新回答；新旧回答均保留，用户可以切换查看。
- 活跃回复期间再次提交消息时，平台按 Runtime 实际能力接收补充指令或明确提示繁忙，不为同一会话启动第二个并发回复。
- 用户离开页面后，已经提交的长任务继续处理。返回原会话后，可以看到处理状态、已有输出、失败原因和最终结果。
- 展开查看执行详情。详情展示 Agent 提供的过程摘要，以及平台实际获得的模型调用和 Connection Action 记录，不展示模型内部思考原文。
- 四个标准模板的模型和推理强度选择。
- 附件上传和结果文件下载。

M1 不支持分享、临时会话或对话分支。

## 12. 附件与会话历史

### 12.1 附件和结果文件

- 四个标准模板的平台对话页和平台托管企微渠道均支持各渠道可传输的附件和结果文件。
- 使用平台交互入口的自定义 Agent，附件和结果文件能力以接入验证结果为准。
- 使用自有交互入口的自定义 Agent 自己负责文件能力。
- 企微渠道按平台 Channel 能力和企微接口限制收发文本、图片、文件或其他媒体，不依赖具体 Runtime 的渠道实现。
- 平台对话页中的附件必须跟随正确的用户和会话传递、展示和隔离。
- 上传前必须展示当前渠道和 Agent 实际支持的文件类型与大小限制，并在上传前拒绝不符合要求的文件。

### 12.2 会话历史

- 平台保存平台对话页和平台托管渠道产生的会话、执行状态和历史。不同渠道的会话不自动合并；企微会话不进入个人 Web 历史列表。
- 历史在 Agent 停止、重启、模板升级或被管理员停用后仍然保留。
- Agent 不可用时，历史只读，用户不能继续发送消息。
- 每位使用者只能查看自己的平台会话。Agent Owner 不能通过平台查看普通使用者的原始会话、个人附件或个人记忆。
- M1 不支持用户删除或导出会话。会话、附件和结果文件的保留遵循公司现有数据政策，Agent 平台不单独设置保留期限。
- 自有交互入口的会话历史由自定义 Agent 自己处理，不进入平台历史。

## 13. 平台操作审计

以下操作必须形成审计记录。独立的操作审计页属于 M1 次要优先级，不作为首发阻塞项：

- Agent 创建申请、审批和驳回。
- Owner 和可用范围变更。
- Agent 停止、重启和停用。
- 自定义镜像 Tag/Digest 变更、标准模板升级和回滚。
- 企微渠道绑定变更。
- 标准模板的模型清单和默认项变更。
- 环境变量变更和 Secret 替换；审计不记录 Secret 值。
- Agent 可用的 Provider 和 Action 变更。
- 用户对 Connection 的授权、更新确认和撤销。
- 用户使用 Agent 的时间、渠道和结果状态，不记录会话内容。

平台操作审计与 Connection 调用审计分别由两个系统提供。两类记录必须能够关联同一次 Connection 调用。审计不记录聊天内容、模型内部思考或 API Key 明文。

## 14. 上线验收

| 场景 | 验收结果 |
| --- | --- |
| 四个标准模板 | Codex、Claude、OpenCode 和 Pi 均能完成申请、审批、创建和真实任务；平台 Web、平台托管企微、模型选择、附件与结果文件和 Connection 可用 |
| 模板升级 | 已有 Agent 自动升级；平台配置、渠道、历史、平台数据和原 PVC 保留；失败时可以恢复旧镜像和 Workload 配置，并明确提示 Runtime 数据兼容风险 |
| 自定义 Agent | 公司 Hub 镜像固定为不可变 Digest；同名 Tag 变化不自动影响已有 Agent；只有 Owner 选择 Tag 才升级；自有交互入口或通过 ACP 验证的平台入口至少有一个可用 |
| Base Image | 公司 Hub 中存在可正常继承和构建的 Base Image，不要求预集成额外能力 |
| Owner 与账号禁用 | Agent 始终保留有效 Owner；系统管理员可以完成离职交接；禁用账号不能继续使用或管理 Agent |
| 权限与隔离 | 未授权用户无法发现或使用 Agent；组织变化立即生效；多人使用时会话、文件、记忆和运行上下文相互隔离 |
| 并发与可用性 | 多人同时提交消息时各自看到独立处理状态；繁忙、启动、更新和失败均有明确反馈，不静默丢失消息 |
| 企微群聊 | 未授权发送者不能触发 Agent；共享线程不读取个人数据；Connection 只使用消息发送者的授权 |
| 自有交互入口 | 自定义 Agent 负责自己的协议、身份、会话和历史；使用平台身份入口时不能绕过公司身份及 Agent 可用范围校验 |
| 模型配置 | 使用者选择从下一条消息生效；企微使用默认项；选项移除或凭证失效时有明确回落或错误提示 |
| Connection | 至少一个真实外部平台完成连接、账号选择、授权、Action 调用、扩权确认和撤销；原始凭证不进入 Agent |
| 生命周期 | 撤回申请、停止、重启、失败重试和管理员停用符合管理状态与服务可用性规则 |
| 文件与历史 | 平台入口按能力收发文件；平台历史在停止、重启、升级和停用后保留并按个人或群聊范围隔离；自有入口历史不进入平台 |
| 环境变量 | 标准模板只接受平台为该模板开放的 env/Secret 键并拒绝其他键；自定义 Agent 可使用任意非 `AGENT_INFRA_*` K/V；标准模板的平台模型配置最终生效；Secret 不回显且只能替换 |

## 15. Roadmap

Roadmap 只记录产品方向和优先级，不在本 PRD 展开实现方案。

### 高优先级

- Eval 与指标。
- Skill Hub。
- 可视化模板管理。

### 中优先级

- 平台级 Sandbox 能力。
- Agent 删除。
- 通过 Connection 接入知识能力。
- 多 Agent 协作。

### 低优先级

- Agent API、Webhook 和定时任务。
- 审批及运行状态的主动通知。
- 通过 Connection 动态推送或拉取镜像。
