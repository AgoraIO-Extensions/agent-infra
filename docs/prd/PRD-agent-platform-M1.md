# 企业级 Agent 平台 M1 产品需求

## 1. 产品目标

企业级 Agent 平台面向企业员工及内部应用。M1 支持基于部署提供的标准模板，或部署批准的 OCI Registry 中已有的自定义 Agent 镜像，创建并使用一个长期运行的 Agent；调用方也可以通过 API 管理 Agent 并提交后台任务。

M1 同时交付 Agent 平台和独立的 Connection 系统。Agent 平台负责 Agent 的创建、权限、运行和使用体验；Connection 系统负责外部平台接入、账户鉴权和用户授权。

M1 上线后应形成以下闭环：

1. 员工可以申请创建 Agent，系统管理员通过审批控制服务器资源占用。
2. Agent Owner 可以配置共同 Owner、可用范围和使用渠道。
3. 获得权限的员工可以通过平台对话页、平台托管企微渠道或自定义 Agent 的自有交互入口使用 Agent。
4. 同一个 Agent 可以服务多人；平台入口中的不同用户会话和数据相互隔离。
5. 标准模板由平台持续升级，已有 Agent 自动获得更新。
6. 用户或应用可以通过 API 创建、启动 Agent，提交、查询和取消自己的任务；平台负责拉起运行实例和调度任务。
7. Agent 或客户端使用执行主体独立获得的授权，直连 Connection 的 MCP/API 使用外部平台能力。
8. 调用方能查看任务过程，运维能定位运行故障；平台团队和 Owner 能通过评测和主动反馈分析模型及 Agent 效果。
9. 治理、执行和外部操作可审计，并能在各自授权范围内关联查询。

### 1.1 依赖与边界

- 平台使用部署提供的身份和组织体系，不维护独立用户目录，也不限定具体认证或目录协议。
- 部署提供获准的模型端点目录。Owner 为每个 Agent 选择端点，并配置独立访问凭证、模型和推理强度；模型供应商接入、路由、成本、预算、配额和故障切换不属于 Agent 平台。
- 自定义 Agent 只使用部署批准的 OCI Registry 中已有的镜像。镜像构建、签名、扫描和 Registry 准入由部署政策负责。
- M1 不提供统一的 Sandbox。标准模板和自定义 Agent 可以使用自身已有的执行工具；平台不规定这些工具在 Pod 内还是外部服务中运行。

## 2. 用户角色

员工、Agent Owner 和系统管理员承担人员职责；应用以独立身份调用 API。

### 2.1 员工

- 浏览并使用自己有权访问的 Agent。
- 提交 Agent 创建申请，并查看申请状态。
- 建立自己的 Connection，并决定是否授权给某个 Agent 使用。

### 2.2 Agent Owner

- 用户创建 Agent 时，该用户成为 Owner；应用创建时，由应用登记的人类责任人成为 Owner，创建主体仍记录为应用。
- 可以增加或移除共同 Owner；所有 Owner 权限相同。
- Agent 必须始终保留至少一名有效 Owner。创建者不是不可移除的特殊 Owner。
- 配置 Agent 的可用范围和使用渠道。
- 为标准模板配置模型清单及默认项。
- 在有权使用的 Agent 和评测数据范围内运行评测、分析效果，并查看线上反馈汇总；Owner 身份不授予其他主体的任务内容访问权。
- 为 Agent 配置环境变量和 Secret。
- 为自定义 Agent 选择新的镜像 Tag 并发起升级。
- 停止、重启 Agent，并重试创建失败的 Agent。

### 2.3 系统管理员

- 批准或驳回 Agent 创建申请。
- 停用 Agent 并撤销其运行资格。
- 代替 Owner 重试创建失败的 Agent。
- 在 Owner 账号被禁用或离职后增加、移除或替换 Owner。
- 查看平台操作审计。

### 2.4 应用与责任人

- 内部应用或服务使用独立应用身份，独立获得 Agent 创建、管理、使用及 Connection 调用权限，不继承责任人的个人权限。
- 应用登记有效的人类责任人，由责任人管理应用及其 API 凭证。责任人身份不自动授予应用或其他主体的任务、会话及附件访问权。
- 用户与应用都是调用主体，任务归属于实际提交主体。API 凭证和授权规则见 7.3。

## 3. Agent 运行方式

- 一个 Agent 对应一个长期存在的独立 Pod，不按用户或会话创建 Pod。
- 一个 Agent 可以授权给多人使用，不是创建者的个人专属实例。
- 同一个 Agent 被多个主体使用时，各自只能看到自己的消息和处理状态。Web 消息提交后立即显示已提交或处理中；无法接收时明确提示繁忙并允许重试，不能静默丢弃消息。API 的有界等待规则见 10.4。
- Agent 身份稳定，运行实例可复用，任务结束后保留实例及持久工作区。平台负责按 Agent 能力投递任务，调用方无需直接管理 Worker。
- M1 不承诺固定并发数量，不提供实例池、自动休眠、任务优先级或跨 Agent 编排。
- Agent 停止时释放计算资源，但保留平台配置、渠道绑定、会话历史和用户数据。
- Agent 被系统管理员停用后同样释放计算资源，并保留上述数据。
- M1 不支持删除 Agent，也不设置运行资格期限。

## 4. 标准模板

M1 首发四个标准模板。

| 模板 | 主要场景 | 平台对话页 | 平台托管企微 | 模型选择 | 附件与结果文件 | Connection |
| --- | --- | --- | --- | --- | --- | --- |
| Codex | 编程任务 | 支持 | 支持 | 支持 | 支持 | 支持 |
| Claude | 通用知识工作 | 支持 | 支持 | 支持 | 支持 | 支持 |
| OpenCode | 开源编程 Agent | 支持 | 支持 | 支持 | 支持 | 支持 |
| Pi | 可扩展 Agent 工作流 | 支持 | 支持 | 支持 | 支持 | 支持 |

四个标准模板均须支持平台任务 API、真实模型及工具调用观测和统一评测闭环，分别按第 10、14、15 节验收。

标准模板由平台团队通过部署运维方式在获准的 OCI Registry 和模板目录中登记、升级和停用。M1 不建设可视化模板管理后台。

模板升级后，基于该模板创建的所有 Agent 自动升级。Owner 不能锁定旧版本、延迟升级或自行回滚。升级和平台回滚保留 Agent 配置、渠道绑定、平台会话历史、平台数据和平台为 Runtime 管理的原有持久数据，但不保证 Runtime 自有数据能够兼容旧版本。平台团队在回滚或降级前必须评估并提示该风险。

升级不影响使用时，产品不展示技术过程。升级期间暂时不能使用时，对话页展示“更新中”，历史保持只读。升级失败时，平台先自动恢复旧版本；恢复成功后继续提供旧版本并向 Owner 显示失败原因，只有旧版本也无法恢复时才展示“暂时不可用”，由平台团队人工恢复。产品不能在更新期间接收消息后静默丢弃。

## 5. 自定义 Agent

### 5.1 准入与部署

- M1 只接受部署批准的 OCI Registry 中已经存在的 Agent 镜像，不接收源码，也不在平台内构建镜像。
- 部署提供的镜像准入能力是自定义 Agent 的来源边界。平台校验镜像已获准且提交主体有权使用，并在 Web 创建审批通过后、API 创建受理后或后续升级过程中验证镜像满足 5.3 的交互入口和基本可用性要求；这些验证不增加源码审查或镜像审批。
- 创建或升级自定义 Agent 时，平台把 Tag 解析并固定为当时实际对应的不可变镜像 Digest。同名 Tag 后续发生变化，不能改变已经创建的 Agent。
- 自定义 Agent 不需要登记为标准模板，也不增加镜像审批或源码审查。平台不根据 Base Image 或父镜像血缘推断最终能力。
- 自定义 Agent 使用平台预设的标准资源规格，Owner 不能选择或修改 CPU、内存、副本数和弹性策略。
- Web 创建自定义 Agent 需要系统管理员审批，用于控制服务器资源占用；API 创建按 7.3 校验权限并审计，不需要审批。

### 5.2 Base Image

M1 在部署批准的 OCI Registry 中提供一个可供自定义 Agent 继承的 Base Image，帮助开发者形成统一的 `FROM` 使用方式。

M1 的 Base Image 不要求预集成身份、消息、Connection 或其他平台能力。它只为开发者提供统一的父镜像。使用 Base Image 是推荐方式，不是部署前提，也不会成为新的准入或审批条件。Base Image 和镜像继承只描述构建关系，不是平台运行类型。

### 5.3 交互入口

自定义 Agent 创建时必须选择一种交互入口归属：

- **自有交互入口：** Agent 自己提供人机交互应用并负责协议、会话、历史、附件、模型和使用体验。平台负责部署、生命周期、镜像版本、资源、环境变量、Secret、基础安全和访问地址发布；Owner 必须在由自定义 Agent 自己校验身份与权限和使用平台身份入口之间选择一种，平台保存该选择并只发布对应入口。此类交互不进入平台会话和历史，具体责任边界见 7.2。
- **平台交互入口：** Agent 使用平台对话页和平台托管渠道。M1 的自定义 Agent 只通过 ACP 接入，并在创建或升级时完成核心兼容性验证。平台负责身份、会话、历史和渠道体验，实际可用的模型、附件、结果文件和 Connection 能力由接入验证结果决定。

创建时选择的交互入口归属必须与镜像声明一致；不一致则创建失败，升级时不一致则拒绝升级并继续提供旧版本。

选择平台交互入口但镜像未声明或未通过 ACP 核心兼容性验证时，创建失败或升级被拒绝。平台不为其他未知协议增加专用接入。

### 5.4 模型、文件与 Connection

- 使用自有交互入口时，模型、文件和外部调用由自定义 Agent 自己负责，平台不展示或管理这些能力。
- 使用平台交互入口时，平台只展示接入验证确认支持的模型、附件和结果文件能力。
- 使用平台交互入口且接入验证确认支持模型选择时，平台对话页展示 Runtime 通过 ACP 提供的当前模型选项并转发使用者选择；模型选项、默认项、Base URL 和凭证仍由镜像及 Owner 通过自定义 Agent 的环境变量或 Secret 管理，不进入第 8 节的标准模板模型配置。提交消息前平台再次确认所选模型仍然有效；失效时拒绝提交并明确提示，不自动切换其他模型。Runtime 未提供该能力时，平台不展示模型选择。
- Connection 是自定义 Agent 的可选能力。接入时由 Agent 或客户端直连独立 Connection MCP/API，遵循第 9 节的授权和审计关联规则；Agent 不能获得外部账号原始凭证。
- 平台只展示经接入验证的 Connection 能力及独立管理入口。未经过 Connection 的自有外部调用由自定义 Agent 负责。
- Agent 管理 API 不意味着自有交互入口已兼容平台任务协议。自定义 Agent 的任务 API、模型及工具观测和 Eval 能力以实际接入验证为准，不支持的能力须明确告知调用方。

### 5.5 环境变量与 Secret

- 每个标准模板只开放平台为该模板定义的受控环境变量和 Secret。Owner 只能配置其中明确开放的键；其他键在保存前被拒绝。
- 自定义 Agent 允许 Owner 配置任意环境变量和 Secret K/V，包括 Runtime 约定的标准变量和镜像自定义变量。
- `AGENT_INFRA_*` 是平台保留前缀，Owner 不能覆盖；该限制同时适用于标准模板和自定义 Agent。
- 标准模板的模型 Base URL、API Key、模型和推理强度以第 8 节的平台模型配置为准；同名的 Owner 环境变量或 Secret 不能覆盖该配置。
- 普通值可以回显和修改。Secret 加密保存、不回显且只能替换。
- 环境变量和 Secret 变更由平台安全注入 Agent，不要求重新审批。

### 5.6 升级与回滚

自定义 Agent 默认保持当前固定的不可变镜像 Digest，不自动跟随 Hub 中 Tag 的变化。只有 Owner 明确选择或重新选择 Tag 并执行升级时，平台才采用当时对应的新 Digest。同名 Tag 指向新 Digest 时可以提示 Owner，但不能自动切换。

新版本先作为候选版本验证，M1 升级不能切换交互入口归属。候选版本满足当前交互入口和基本可用性要求后，平台才完成升级并保留原渠道绑定；验证期间无法继续提供旧版本时，用户看到“更新中”。

候选版本验证失败时，平台继续提供或恢复旧版本，不更新渠道绑定；只有旧版本也无法恢复时，Agent 才进入“暂时不可用”。升级和回滚保留平台管理的 Owner、可用范围、渠道绑定、平台会话历史、平台数据和平台为 Runtime 管理的原有持久数据。平台不自动创建持久数据快照，也不保证 Runtime 自有数据能够兼容旧版本；Owner 主动降级前必须看到该风险。

## 6. 创建与审批

### 6.1 创建申请

本节的申请与审批适用于 Web 创建渠道；API 直接创建按 7.3 和 10.4 执行。所有公司员工都可以通过 Web 提交申请，内容包括：

- Agent 名称和说明。
- Agent 来源：标准模板或部署批准的 OCI Registry 中的自定义 Agent 镜像。
- 自定义 Agent 的 OCI 镜像引用和交互入口归属。
- 自有交互入口的身份责任选择。
- 共同 Owner。
- 可用范围。
- 标准模板的模型清单及默认项。
- 环境变量和 Secret。

### 6.2 审批规则

- M1 只允许系统管理员审批。
- 审批通过前不创建 Pod。
- 审批页展示 Agent 使用的预设资源规格和预计资源占用。
- 系统管理员可以批准或驳回；驳回原因必填。
- 申请人可以修改原申请后重新提交，无需创建新申请。
- 申请人可以在待审批时撤回申请。撤回后不创建 Agent，原申请只作为历史记录保留；再次申请时需要提交新申请。
- Agent 获得运行资格后，停止、重启、模型、权限和渠道调整不需要重新审批。
- M1 不发送审批、创建成功或创建失败的邮件及企微通知，用户在 Web 查看状态。

### 6.3 管理状态

Agent 申请、列表和详情页只展示以下管理状态：

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| 待审批 | 申请等待系统管理员处理 | 修改申请、撤回申请 |
| 已撤回 | 申请人主动撤回，未创建 Agent | 查看历史记录 |
| 已驳回 | 申请未通过 | 查看原因、修改后重新提交 |
| 创建中 | Web 审批通过或 API 创建已受理，正在创建 | 查看状态 |
| 可用 | Agent 已获得运行资格 | 停止、重启、配置、使用 |
| 已停止 | Owner 主动停止 | Owner 可以重启 |
| 创建失败 | 创建已受理但未完成 | Owner 或系统管理员可以重试 |
| 已停用 | 系统管理员撤销运行资格 | Owner 不能恢复 |

创建失败后再次重试仍然失败，状态保持“创建失败”，并保留再次重试入口。已停止和已停用均不占用 Agent 计算资源。

### 6.4 服务可用性

管理状态为“可用”时，Web 另外展示当前服务可用性。API 在启动或更新期间的任务受理见 10.4：

| 服务可用性 | 用户看到的行为 | Owner 可执行操作 |
| --- | --- | --- |
| 正常 | 可以发送消息并获得回复 | 正常管理和使用 |
| 启动中 | 历史只读，暂时不能发送消息 | 查看状态 |
| 更新中 | 历史只读，暂时不能发送消息 | 查看说明 |
| 暂时不可用 | 展示失败原因和重试提示，历史只读 | 重启 |

Pod、进程和运行时名称等技术状态不在 M1 产品界面展示。

## 7. 权限与用户隔离

### 7.1 可用范围

- 平台不区分发现权和使用权，每个 Agent 只维护一套可用范围。
- 可用范围支持指定员工、公司组织和独立应用；应用权限不随责任人的个人权限变化而继承或扩张。
- 通过平台提供的入口时，用户或应用只能发现和使用自己在可用范围内的 Agent；自有交互入口的责任边界见 7.2。
- 创建主体的初始管理、使用授权见 7.3；人类 Owner 的确定与交接见第 2 节。
- 普通使用者不能修改 Agent 的全局配置。
- 平台在每次使用平台提供的入口前都按当前公司账号状态和组织成员关系判断权限。权限来自公司组织时，员工调岗或退出该组织后立即失去由该组织获得的权限；直接指定给员工的权限只在该员工被移出可用范围后失效。
- 公司账号被禁用后，用户不能继续登录平台、通过平台入口使用或管理 Agent。主体禁用及撤权后的任务处理见 7.3；Connection 在其独立入口校验当前身份和授权，平台不代替 Connection 管理账号生命周期。

### 7.2 多用户隔离

同一个 Agent 被用户或应用使用时，必须按实际主体隔离各自的：

- 会话。
- 文件和附件。
- 个人记忆。
- 运行上下文。

标准模板和使用平台交互入口的自定义 Agent，由平台在每次交互时解析当前用户或应用、Agent 和入口权限，并要求 Runtime 隔离不同主体的会话、文件、记忆和运行上下文。平台不规定各 Runtime 的进程或 Sandbox 实现方式。

使用自有交互入口的自定义 Agent 自己负责身份、权限和数据隔离；其交互不属于平台会话。平台统一发布访问地址，Owner 只选择身份责任，不自行管理底层网络资源。选择自有身份入口时，自定义 Agent 必须在服务端完成身份和权限判断，不能信任调用方提交的身份字段；账号生命周期、停用、撤权、会话终止和权限范围由 Owner 及其身份体系负责，平台不向该入口同步公司账号或 Agent 可用范围变化。需要公司账号禁用和 Agent 可用范围变化立即生效时，Owner 必须选择平台身份入口，由平台在每次请求中校验当前公司账号和 Agent 可用范围。

企微群聊中的消息和 Agent 回复对群成员共享可见，不适用“不同用户看不到群内公开内容”的规则。公开可见不代表共享 Runtime 上下文；Channel 层按发送者隔离 Platform Conversation 和 Runtime Session，任何参与者的消息、个人附件、个人记忆和个人 Connection 结果都不能进入其他发送者的 Runtime 上下文。详细规则见 10.3。

### 7.3 API 身份、凭证与授权

- API 同时支持用户与独立应用身份。身份、组织和有效权限由服务端从可信凭证及权威授权关系解析；调用方提交的身份字段不能改变主体或任务归属。
- API 操作需要鉴权、授权和审计，不增加逐次审批或预审批。创建需要创建权限，生命周期操作需要对应 Agent 管理权限，提交任务需要 Agent 使用权限。
- 创建成功后，平台向创建主体显式授予新 Agent 的管理和使用权限并记录审计；两项授权可独立撤销。该授权不扩大所用 API 凭证的操作范围，Owner 身份不能绕过已撤销的 API 授权。
- 用户管理个人 API 凭证；应用责任人管理应用 API 凭证。凭证支持操作范围、有效期和单独撤销，有效权限始终不超过所属主体的当前授权；凭证值不进入普通读取结果、日志或审计。
- 查询任务进度、结果、结果流和取消任务均限于本主体提交的任务，并要求当前 Agent 使用权及相应凭证权限。Owner 或应用责任人不能凭角色读取或取消其他主体的任务，也不能探知不可见任务是否存在。
- 凭证到期或撤销后，该凭证的 API 访问和结果流终止，已受理任务继续执行。同一主体可用另一有效且具备所需权限的凭证查询或取消，其他主体不能接管。
- 用户或应用被禁用，或失去 Agent 使用权后，平台拒绝新任务、向进行中任务发出取消请求并阻止后续受控操作；尚未执行的任务不得继续投递。系统取消与调用方的取消权限分开处理，取消不撤回已发生的外部效果。
- 应用在 Connection 中独立获得调用授权；Platform API 凭证不能充当 Connection 访问凭据，详见第 9 节。

## 8. 标准模板的模型配置

本章适用于四个标准模板。

Owner 配置的是部署提供的模型端点目录中的访问选项。Agent 平台不负责模型供应商接入、模型路由、成本、预算和配额管理。

### 8.1 Owner 配置

- Owner 配置允许使用的模型清单。
- 每个选项引用目录中获准的 Base URL 和该 Agent 独立配置的加密 credential，并包含模型名和允许的推理强度。API Key 只作为一次性 Secret 输入提交，不能出现在模型选项响应或普通配置读取结果中。
- Base URL 只能从部署提供的目录中选择，Owner 不能提交或覆盖任意地址。
- API Key 加密保存且不回显，只能替换。
- 普通使用者看不到 Base URL 和 API Key。
- Owner 必须设置默认模型和默认推理强度。
- Owner 只配置一个选项时，相当于固定模型。

模型配置保存前必须验证 Base URL、API Key 和模型是否可用。该验证只确认连通性；回答质量与 Agent 效果按第 15 节评估。

### 8.2 使用者选择

- 平台对话页的使用者可以从 Owner 配置的清单中选择模型和推理强度。
- 同一会话中可以切换，变更从下一条消息开始生效，不改变已有消息。
- 切换模型不要求新建会话。
- 企微入口始终使用 Owner 设置的默认模型和推理强度，不提供切换命令。
- Owner 删除会话当前使用的模型选项后，该会话从下一条消息开始切换到默认选项，并向使用者说明变化。
- API Key 失效、额度不足或模型不可用时，产品展示可理解的原因和稍后重试或联系 Owner 的入口，不向普通使用者展示 API Key。

Owner 保存配置后自动生效。底层如需重启 Pod，由平台处理，不向用户展示技术过程。

## 9. Connection 集成

Connection 是与 Agent 平台并行建设的独立系统。详细需求见 [Connection M1 产品需求](PRD-connection-M1.md)。

Agent 平台与 Connection 的边界如下：

- Agent 或客户端直接调用 Connection MCP/API。Platform 不代理调用、不签发代调用证明，不管理 Connection 的 Provider/Action 目录、账号、授权或状态及审计投影。
- Platform 校验自身 API 身份、Agent 权限和任务归属，仅保存自身任务、模型及工具执行事实与审计。Connection 独立校验直连客户端的用户或应用身份及当前授权，并保存外部账号、凭证、授权、外部调用结果和审计。
- 用户或应用在独立 Connection 入口管理自己有权使用的个人或公司 Connection 及调用授权；Agent Owner 不能替其他主体选择外部账号或授予 Connection 权限。能力扩张须由授权主体在 Connection 确认，撤权后由 Connection 拒绝新调用。
- Connection 的直连客户端访问凭证与 Platform API 凭证分别管理；外部账号原始凭证始终保留在 Connection，Agent、模型和调用方不能获得。
- M1 必须能从实际执行定位对应的直连调用，并通过真实调用产生的关联信息核对两侧审计。两侧各自在授权入口查询，不在 Platform 复制 Connection 状态或审计；关联标识不授予访问权，也不能仅凭调用方提交的相同字符串认定关联成立。
- 四个标准模板必须完成 Connection 接入；首个受监督 Connection Pilot 仅使用 Codex 标准模板、两个测试用户、专用 GitHub 测试账号和一个受控 private 仓库，验收读取、真实创建 PR、隔离、幂等、审计和撤权；Pilot 通过结论不能外推到其他模板、账号、Provider 或生产环境。

## 10. 使用渠道

### 10.1 统一身份

平台对话页和平台托管企微渠道统一映射到公司用户身份。Channel 层在每次使用前校验 Agent 可用范围，并把渠道会话映射为平台会话；Runtime 不重复维护用户白名单或渠道身份规则。

### 10.2 渠道绑定

- 平台对话页和平台托管企微渠道对四个标准模板始终可用。
- 使用平台交互入口的自定义 Agent 通过兼容性验证后，可以使用平台对话页和平台托管企微渠道。
- 每个支持平台托管企微渠道的 Agent 独立绑定自己的企微智能机器人或企微自建应用。
- 四个标准模板或通过兼容性验证、使用平台交互入口的自定义 Agent 创建成功后，Owner 可以按需绑定企微渠道；使用自有交互入口的自定义 Agent 不能绑定平台托管企微渠道。
- Owner 使用部署环境的企微流程取得机器人或应用配置，平台只负责绑定和校验，不负责签发企微凭证。
- 平台不建设全公司统一的企微 Agent 入口。
- 渠道变更不需要重新审批，但必须记录操作。

### 10.3 企微会话

- 企微智能机器人支持单聊和群聊。
- 每条企微消息都必须通过部署身份能力映射到当前发送者。无法映射身份，或发送者不在 Agent 可用范围内时，机器人不调用 Agent，并回复“暂无权限使用此 Agent”。
- 群消息和 Agent 回复对群成员可见。Agent 可用范围只决定谁能触发 Agent，不能阻止其他群成员阅读群内已有内容；Owner 绑定群聊时必须看到该提示。
- Channel 层按 Agent、渠道绑定、会话类型、群聊或线程以及当前发送者生成稳定的会话映射；同一群或线程中的不同发送者使用不同 Platform Conversation 和 Runtime Session。Runtime Adapter 不自行改变该映射。
- 群聊中调用 Connection 时，只能使用触发本次调用的消息发送者已经授权给该 Agent 的 Connection。其他群成员的 Connection 和授权不能被使用。
- Web、企微智能机器人和企微自建应用之间不合并会话。

### 10.4 Agent API 与后台任务

API 提供创建、启动、停止和重启 Agent，以及提交、查询、订阅结果和取消任务的完整闭环；权限和审批边界见 7.3。

| 行为 | 产品要求 |
| --- | --- |
| 创建与启动 | 创建返回稳定 Agent 标识和创建状态；平台负责拉起独立运行实例。已停止的 Agent 须显式启动，故障须先完成有效恢复；Owner 不能恢复被管理员停用的 Agent |
| 异步受理 | 向指定 Agent 提交任务，只有任务已可靠保存才返回受理成功和稳定执行标识；调用方断线或停止订阅不取消任务 |
| 会话上下文 | 默认新建会话，也可显式续接本主体在该 Agent 下的已有会话。每个任务有独立执行标识，同一会话沿用上下文；不得续接其他主体的会话或静默替换不可恢复的会话 |
| 有界调度 | 同一会话的任务串行执行，不同会话在 Agent 能力范围内并发；等待容量和时长有界。启动或更新中可以可靠受理并等待，容量已满则在受理前拒绝，已受理任务等待超时则明确失败 |
| 不可受理 | Agent 已停止、已停用或故障未恢复时拒绝任务，并告知原因与可行操作；不能用提交任务隐式恢复运行资格 |
| 过程与结果 | 可按执行标识查询状态、已有输出、失败原因和最终结果，并订阅增量输出；重新连接能继续查看已有内容。模型、工具和结果文件按 Agent 已验证的能力呈现 |
| 重复请求 | 创建 Agent 和提交任务支持幂等：相同主体、操作及幂等标识的相同请求返回原对象，不重复创建或执行；内容冲突明确拒绝 |
| 取消 | 未开始的任务取消后不再投递；运行中的任务先显示取消请求已受理，确认停止后才显示已取消。停止未确认前，同一会话不能开始下一任务；已发生的外部操作不会回滚 |
| 重启与恢复 | 已受理但未开始的任务在服务重启后继续处理。运行中任务能恢复时沿原执行和会话继续，不能恢复则明确失败；结果不确定时标记待核实并阻止受影响会话继续执行，不能盲目重放可能产生外部效果的任务 |

API 对同会话后续任务采用有界等待；Web 在活跃回复期间仍按 11.2 接收补充指令或提示繁忙，不自动改为排队任务。两种入口都不能并发改变同一会话上下文或静默丢失已受理内容。

## 11. Web 产品体验

### 11.1 页面

M1 提供以下页面：

- Agent 列表：展示当前用户有权使用的 Agent。
- Agent 详情：展示 Agent 说明、Owner、可用渠道、模型选择范围和所需 Connection 能力，并提供可用的使用入口。
- 对话页：提供 ChatGPT 式对话和个人历史会话。
- 我的 Agent：查看申请状态，管理自己作为 Owner 的 Agent。
- 创建与配置页：提交申请并管理 Owner、可用范围、模型、渠道、环境变量和 Secret。
- API 凭证与应用管理入口：用户管理个人凭证，责任人管理应用及其凭证，管理者在权限范围内维护应用的 Agent 授权。
- 我的 Connection：进入独立 Connection 系统，按其权限管理账号和调用授权。
- 审批页：系统管理员审批申请和停用 Agent。
- 操作审计页：系统管理员按职责查询平台审计及关联详情，为 M1 必需入口，权限见第 13 节。
- 运行观测入口：运维查看平台健康、运行指标、故障与告警；调用方从自己的任务进入执行详情。
- 评测入口：平台团队和获授权 Owner 管理评测集、实验、对比结果和失败样本；对话页支持使用者主动反馈。

自定义 Agent 的自有交互入口不属于平台对话页。平台可以在 Agent 详情中展示已配置的访问入口；使用平台身份入口时由平台完成身份和权限校验，但平台不接管其交互体验和历史。

### 11.2 对话能力

平台对话页支持：

- 新建会话和查看历史会话。
- 流式回复、停止回复和重新生成。
- 停止请求保存成功后显示“正在停止”，并由平台异步交给 Runtime；只有当前回复的发送者可以停止，重复请求或 Worker 重启不能让停止命令丢失或产生第二次副作用。已经提交给外部 Provider 的操作不自动撤回。
- 重新生成基于同一条用户消息产生新回答；只有当前会话没有活跃回复时才能发起，重复请求不会产生重复回答版本，新旧回答均保留，用户可以切换查看。
- 活跃回复从首条消息提交成功时开始，包含尚未交给 Runtime 或投递结果暂时不确定的阶段，直到回复成功、失败或取消。同一发送者再次提交消息时，平台按 Runtime 实际能力接收补充指令或明确提示繁忙；平台不为同一会话启动第二个并发回复。
- 补充指令提交成功后，原回复在 Runtime 接受前失败或取消时，该消息显示“投递失败：原回复未开始”；原回复已开始但在补充指令实际投递前结束时，该消息显示“投递失败：原回复已结束”。两种情况都提供重新发送入口；平台不能静默丢弃、自动创建新回复或把消息改绑到其他回复。
- 补充指令实际交给 Runtime 前再次校验发送者当前身份、组织成员关系和 Agent 可用范围；权限已失效时，该消息显示“投递失败：权限已失效”且不交给 Runtime。
- 用户离开页面后，已经提交的长任务继续处理。返回原会话后，可以看到处理状态、已有输出、失败原因和最终结果。
- 展开查看执行详情。详情展示 Agent 提供的过程摘要及实际获得的模型、工具执行记录，具体可观测要求见第 14 节；不展示模型内部思考原文。
- 四个标准模板的模型和推理强度选择；通过接入验证的自定义平台入口按 5.4 展示 Runtime 提供的模型选项。
- 附件上传和结果文件下载。

M1 不支持分享、临时会话或对话分支。

## 12. 附件与会话历史

### 12.1 附件和结果文件

- 四个标准模板的平台对话页和平台托管企微渠道均支持各渠道可传输的附件和结果文件。
- 使用平台交互入口的自定义 Agent，附件和结果文件能力以接入验证结果为准。
- 使用自有交互入口的自定义 Agent 自己负责文件能力。
- 企微渠道按平台 Channel 能力和企微接口限制收发文本、图片、文件或其他媒体，不依赖具体 Runtime 的渠道实现。
- 平台对话页中的附件必须跟随正确的用户和会话传递、展示和隔离。
- 上传前必须展示当前渠道和 Agent 实际支持的文件类型与大小限制，并在上传前拒绝不符合要求的文件。

### 12.2 会话历史

- 平台保存平台对话页、平台托管渠道和任务 API 产生的会话、执行状态和历史，均归属于实际提交主体。不同渠道的会话不自动合并；企微会话不进入个人 Web 历史列表。
- 历史在 Agent 停止、重启、模板升级或被管理员停用后仍然保留。
- Agent 不可用时，Web 历史只读，用户不能继续发送消息；API 在启动和更新期间按 10.4 有界受理。
- 单个 Platform Conversation 的 Runtime Session 恢复失败时，只有该会话标记为“会话不可用”：历史只读且不能继续发送消息，也不能静默创建新 Session。其他会话和 Agent 服务保持正常，用户可以明确新建会话。
- 用户或应用只能查看自己的平台会话。Agent Owner 和应用责任人不能凭角色读取其他主体的原始会话、附件或记忆；独立授权的评测数据不改变原会话权限。
- M1 不支持用户删除或导出会话。会话、附件和结果文件的保留遵循部署环境的数据政策，Agent 平台不单独设置保留期限。
- 自有交互入口的会话历史由自定义 Agent 自己处理，不进入平台历史。

## 13. 平台操作审计

M1 必须提供审计查询 API 和基础管理页面，能查清谁在何时对哪个对象做了什么、是否获得授权，以及实际结果。

### 13.1 记录范围

- 治理：Agent 创建申请、撤回、审批、驳回、API 创建及初始授权，Owner、可用范围和应用授权变更，API 凭证管理。
- 配置与生命周期：Agent 启动、停止、重启、停用及创建重试，镜像变更、模板升级和回滚，模型清单及默认项、企微渠道、环境变量和 Secret 变更。
- API 与执行：访问及授权结果、拒绝原因，任务受理、开始、完成、失败、取消请求及确认、恢复和待核实结果，实际发生的模型与工具操作。
- 结果订阅按建立和结束记录，不逐条复制输出；审计查询本身记录主体、受控查询范围和结果。
- 外部操作：平台记录自身工具执行事实；Connection 独立保存其授权、外部调用、效果、结果及后续处理审计，关联方式见第 9 节。
- Eval：评测集及判定标准版本、数据授权、实验执行、评分与人工复核等管理操作。

记录包括可信操作主体及类型、时间、对象、动作、授权及操作结果，以及适用的请求、执行和关联信息；后台执行须区分原始发起主体和实际执行组件。身份或对象无法确认时如实标记，不能采信或回显请求中的任意自报字段。审计不保存会话或评测正文、附件、模型内部思考、调用证明及凭证值。

### 13.2 查询与权限

- API 和管理页面支持按时间、主体、Agent、动作、结果和执行引用筛选、分页及查看详情。
- 系统管理员按职责查看平台元数据；Connection 管理员在独立系统按职责查询 Connection 审计，两种管理员权限不互相继承。
- 用户或应用可查询自身执行的审计。Owner、应用责任人不因角色获得其他主体的使用记录或任务内容；任务详情仍按原主体授权，关联信息不能绕过任一侧查询权限。

### 13.3 真实结果与可靠性

- 请求尝试可以分别记录，但幂等重试必须指向同一业务操作。受理成功、执行完成和外部效果分别表达，不把取消请求当作取消完成，也不抹去取消前已发生的操作。
- 实际执行系统在外部操作开始前可靠记录调用意图。无法确认的外部结果显示待核实，后续沿原调用核实并保留处理记录；不能通过重发有副作用的请求制造成功结果。
- 审计必须持久保存，不随 Trace 采样丢失。业务状态变更与其必要审计必须一同可靠保存，无法满足时不能返回虚假成功；审计故障不能使拒绝变为放行。
- 审计查询失败须明确报错，不能显示为没有记录。已经发生的外部效果不能因记录或查询故障被描述为未发生。
- 审计故障须可被运维发现；记录的保留和受控清理由部署数据政策规定。

## 14. 运行可观测

### 14.1 调用方的执行详情

- 用户和应用能在自己的任务中查看实际经历的受理、等待、执行、模型及工具调用和结果阶段，按同一次执行串联状态、已确认的耗时和失败原因；技术组件定位由运维入口提供。
- 四个标准模板必须提供真实模型和工具调用信息，不能用整次任务耗时替代模型调用耗时。未采集、无法确认或不支持的数据明确标示，不能推测为成功或零耗时。
- Connection 详情按第 9 节使用真实调用关联，并在独立授权入口查询；平台自己的工具执行记录不能冒充 Connection 外部结果的权威记录。
- 详情遵循原任务的主体隔离；Owner 和应用责任人不因此获得其他主体的会话内容。

### 14.2 运维观测

- 提供日志、指标和 Trace，按一次执行关联 API、等待与投递、Worker、Runtime、模型、工具及结果，定位各阶段耗时、状态和运行故障。
- 运维入口覆盖服务健康、错误和延迟、Agent 可用性与启动、任务积压、流式连接及依赖状态；服务不可用、持续积压和异常错误须有告警。
- 重连或恢复不得重复计算同一事实。观测采集故障须可识别，不改变任务的业务结果；必要审计失败另按 13.3 处理。
- 遥测只保留必要元数据和脱敏错误，不保存普通任务的输入输出正文、模型内部思考、凭证或调用证明。评测内容走第 15 节的独立授权数据流程。

## 15. 模型质量评估与效果分析

M1 提供固定测试集的基线与候选对比、规则和人工及模型评分、逐例分析、人工复核与再次运行，帮助平台团队和 Agent Owner 判断模型、配置或模板变化的效果；用户主动反馈补充线上使用效果。

### 15.1 评测闭环

1. 创建或导入有权使用的测试集，包含输入、必要上下文、任务类型、预期结果或判定标准。样本和标准修改后形成可识别版本，历史实验保留所用版本。
2. 用同一批样本和判定标准运行基线与候选模型、Agent 配置或模板版本。记录实际 Agent、模型、模板或镜像、非敏感配置、数据集及评分器版本；工具环境或其他条件不同须可见，不能将不可比实验当作模型排名。
3. 支持确定性规则、人工评价和依据明确标准的模型评分；展示判定依据、评分来源和评分所用模型，允许人工检查样本并保存独立复核结论。
4. 查看实验历史、汇总及逐例对比，按任务类型分析，下钻获授权样本的输入、输出、判定和失败原因。
5. 维护者修改有权维护的样本或标准后，以新版本再次运行；历史结论保留。重复实验须标明模型随机性或外部环境变化对可比性的影响。

评测复用当前任务受理、查询、取消和 Agent/Connection 授权。四个标准模板均须纳入，自定义 Agent 按实际验证的任务、模型及工具能力纳入；模板版本对比不改变标准模板自动升级及 Owner 不能锁定旧版本的规则。

### 15.2 质量与使用效果

| 维度 | 可查看的结果 |
| --- | --- |
| 回答质量 | 正确性、相关性、指令遵循及结构或格式是否满足标准，以及评分依据 |
| Agent 任务效果 | 是否达到预期结果，工具选择、输入和最终产物是否正确；工具请求成功或任务正常结束不单独证明任务完成 |
| 耗时与用量 | 任务及模型耗时、实际可采集的 Token 用量；缺失明确标记，不引入计费、预算或配额管理 |
| 线上主动反馈 | 使用者可对自己的任务提交有用或无用及问题分类，查看按实际模型、配置版本及时间汇总的数量、反馈率和问题分布；未反馈不表示认可 |

每项统计展示分母、已评分数、缺失及错误数，区分任务执行失败、评分器故障和样本不适用；不能把评分失败当作质量零分或评测通过。可比样本范围和覆盖情况须可见，线上反馈单独展示，不混入离线评测通过率。

### 15.3 数据与执行权限

- 平台团队维护标准模板的获授权测试集；Owner 仅在自己管理且有权使用的 Agent 上，使用有权访问的评测集。获授权应用可按其独立 Agent 和数据权限参与评测。
- 评测样本、输出、评分理由及实验明细是受控业务数据，按评测用途独立授权；Owner 可查看线上反馈汇总，但不能借评测或反馈读取其他主体的原始会话、附件或记忆。
- 线上正文不自动进入评测集。真实材料须先取得明确的评测用途授权并脱敏；原任务访问权不等于评测用途授权，样本导入不提供通用会话分享或导出能力。评测数据的保留、撤权和删除遵循部署数据政策。
- 模型评分所用端点及数据用途须获授权，日志、指标、Trace 和审计不承载评测正文。
- 工具评测使用受控测试环境、账号或响应，不自动重放线上写操作；实际调用仍受当前 Agent 和独立 Connection 授权限制。

## 16. 上线验收

| 场景 | 验收结果 |
| --- | --- |
| 四个标准模板 | Codex、Claude、OpenCode 和 Pi 均能完成 Web 申请审批及 API 直接创建和真实任务；平台 Web、平台托管企微、模型选择、附件与结果文件、Connection、模型及工具观测和评测可用 |
| 模板升级 | 已有 Agent 自动升级；平台配置、渠道、历史、平台数据和平台为 Runtime 管理的原有持久数据保留；失败时可以恢复旧版本，并明确提示 Runtime 数据兼容风险 |
| 自定义 Agent | 获准 OCI 镜像的 Tag 解析并固定为不可变 Digest；同名 Tag 变化不自动影响已有 Agent；只有 Owner 选择 Tag 且新版本满足当前交互入口和基本可用性要求后才升级；失败时保留旧版本和渠道；自有交互入口或通过 ACP 验证的平台入口至少有一个可用 |
| Base Image | 获准 OCI Registry 中存在可正常继承和构建的 Base Image，不要求预集成额外能力 |
| Owner 与账号禁用 | Agent 始终保留有效 Owner；系统管理员可以完成离职交接；禁用账号不能登录平台、管理 Agent 或通过平台身份入口使用 Agent；自有身份入口按 Owner 身份体系执行账号生命周期 |
| 权限与隔离 | 平台入口中未授权用户无法发现或使用 Agent；组织变化立即生效；标准模板和使用平台交互入口的自定义 Agent 被多人使用时，会话、文件、记忆和运行上下文相互隔离 |
| 并发与可用性 | 多人同时提交消息时各自看到独立处理状态；繁忙、启动、更新和失败均有明确反馈，不静默丢失消息；单个 Session 恢复失败只使对应会话不可用 |
| 企微群聊 | 未授权发送者不能触发 Agent；群聊和线程的 Platform Conversation 与 Runtime Session 按发送者隔离；Connection 只使用消息发送者的授权 |
| 自有交互入口 | 自定义 Agent 负责自己的协议、应用和会话历史；平台统一发布访问地址；使用自有身份入口时，未认证或不具备 Owner 身份体系权限的请求被 Agent 服务端拒绝；使用平台身份入口时不能绕过可信 IdentityContext 及 Agent 可用范围校验 |
| 模型配置 | 使用者选择从下一条消息生效；企微使用默认项；标准模板选项移除时明确切换到默认项，凭证失效时提示错误；自定义 Runtime 选项失效时拒绝提交并提示错误，不自动切换其他模型 |
| Connection | 至少一个真实外部平台完成连接、账号选择、授权、MCP/API 直连调用、扩权确认和撤销；通过真实执行关联分别查询两侧审计，跨主体查询被拒绝，自报关联字符串不能伪造绑定；原始凭证不进入 Agent |
| 生命周期 | 撤回申请、停止、重启、失败重试和管理员停用符合管理状态与服务可用性规则 |
| 文件与历史 | 平台入口按能力收发文件；平台历史在停止、重启、升级和停用后保留并按个人或群聊范围隔离；自有入口历史不进入平台 |
| 环境变量 | 标准模板只接受平台为该模板开放的 env/Secret 键并拒绝其他键；自定义 Agent 可使用任意非 `AGENT_INFRA_*` K/V；标准模板的平台模型配置最终生效；Secret 不回显且只能替换 |
| API 身份与直接创建 | 用户和独立应用分别通过 API 创建、启动、停止和重启 Agent，无逐次审批或预审批；创建主体、Owner 和显式初始管理/使用授权正确并可审计，应用不继承责任人权限，凭证范围仍限制后续调用 |
| API 隔离与撤权 | 替换主体、组织、Agent、会话或任务标识不能越权；用户、应用、Owner 和责任人均不能读取、订阅或取消其他主体任务，也不能探知其是否存在；撤销初始授权后立即按当前权限处理 |
| 凭证与主体失效 | 凭证范围、到期和单独撤销生效，旧结果流终止但任务继续，同主体有效凭证可以查询或取消；主体禁用或 Agent 使用权撤销后拒绝新任务及后续受控操作，进行中任务收到系统取消请求 |
| 异步任务与会话 | 受理返回稳定执行标识，断线后仍可查询进度、已有输出和最终结果；默认新会话，显式续接自己的同一 Agent 会话可保留上下文，每个任务执行标识独立 |
| API 调度边界 | 同会话串行、不同会话按能力执行；启动或更新中可靠等待，容量满在受理前拒绝、等待超时明确失败；停止、停用和故障时拒绝任务；Web 仍按补充指令或繁忙规则反馈 |
| 幂等、取消与恢复 | 相同幂等请求返回原对象，内容冲突拒绝；排队任务可取消，运行任务确认停止前不冒充已取消或开始同会话下一任务；重启后未开始任务继续，活跃任务沿原执行恢复或明确失败，未知结果待核实且不盲目重放外部操作 |
| 真实执行观测 | 成功、等待和 Runtime、模型、工具故障均可按执行串起实际阶段、耗时、状态和原因；四模板真实模型及工具数据可查，缺失如实标记，重连与恢复不重复计数，采集故障不篡改业务结果 |
| 运维观测与告警 | 运行后台可查健康、错误、延迟、Agent 启动与可用性、积压、流式连接及依赖状态；服务不可用、持续积压和异常错误可触发告警 |
| 固定集评测对比 | 同一套含回答及受控工具任务的测试集，以两组模型或配置真实运行；可见基线/候选、实际版本、评分依据、耗时及已采集用量，能下钻失败样本、保存人工复核并以新版本再跑，旧结论保留 |
| 评分与主动反馈 | 规则、人工和模型评分均可追溯；任务失败、评分器故障、缺失及不适用分别统计，分母和覆盖可见；主动反馈关联本人任务，未反馈不计正向评价，线上反馈不混入离线通过率 |
| 评测授权与隔离 | 未授权主体无法访问评测集、实验明细或他人任务；线上正文不自动入库，真实材料需评测用途授权并脱敏，评分端点获授权，不自动重放线上写操作，自有交互入口不被推断为兼容评测 |
| 审计查询闭环 | 查询 API 和基础管理页均可用，按条件筛选、分页和关联详情；治理、应用/凭证、执行、模型/工具及 Eval 操作可追溯，查询及订阅起止有记录，后台执行保留原发起人和实际执行组件；两系统权限独立，Owner/责任人不获得他人使用记录 |
| 审计真实性与故障 | 请求尝试关联原幂等操作；受理、执行和外部结果分开，取消保留已发生效果，待核实及后续处理可追溯；必要审计保存失败不返回虚假成功，查询失败不显示空记录，审计不因 Trace 采样丢失 |
| 内容与凭证保护 | 普通任务和评测正文、附件、内部思考、调用证明及凭证不进入日志、指标、Trace 或审计；任务详情和评测内容按各自业务权限读取 |
| 数据生命周期 | 评测数据保留、撤权和删除及审计受控清理遵循部署数据政策，不能因历史可回看而绕过当前授权 |

## 17. Roadmap

Roadmap 只记录产品方向和优先级，不在本 PRD 展开实现方案。

### 高优先级

- Skill Hub。
- 可视化模板管理。

### 中优先级

- 平台级 Sandbox 能力。
- Agent 删除。
- 通过 Connection 接入知识能力。
- 多 Agent 协作。

### 低优先级

- Webhook 和定时任务。
- 审批及运行状态的主动通知。
- 通过 Connection 动态推送或拉取镜像。
