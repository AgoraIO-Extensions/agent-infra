# Agent Infra 使用说明书

面向员工、Agent Owner、系统管理员和接入开发者。本文说明如何使用 Agent 平台与独立
Connection；功能是否可用以当前部署的就绪状态、权限和实际接入验证为准。

## 01 · 先了解两个入口

**Agent 平台**用于选择 Agent、提交创建申请、对话、管理配置与查看执行记录。
**Connection**用于登录外部账号、确认客户端调用授权及查看外部操作记录。两者分别登录、
分别判断权限；平台登录成功不代表已获得 Connection 授权。

| 你想做什么 | 从哪里开始 | 完成标志 |
| --- | --- | --- |
| 使用已有 Agent | 工作区 → Agent 目录 | 有使用权限且服务可用 |
| 创建团队 Agent | 我的管理 → 创建申请 | 审批通过并完成创建 |
| 调整 Agent | 我的 Agent → 配置与生命周期 | 配置保存且服务反馈生效 |
| 连接 GitHub 等平台 | 独立 Connection 控制台 | 账号连接与客户端授权分别完成 |
| 查自己的执行 | 我的执行审计 | 找到对应任务及实际状态 |
| 审批创建申请 | 系统管理 → 创建审批 | 批准或填写原因驳回 |

界面中不可用、未就绪或未开放的能力不能通过本手册启用。本文不宣称任何部署已完成全量
上线验收，也不使用历史 Pilot 结果证明当前版本。API、Eval、Builder、Skill Hub 和自定义
入口的完整生命周期须逐项核对实际部署；没有入口时联系平台团队，不能把需求文档当作已上线功能。

## 02 · 第一次使用：完成一轮对话

开始前，准备公司账号、可使用的 Agent，以及部署要求的个人 Relay Key。

1. 打开团队提供的 Agent 平台地址，使用公司登录入口登录。确认右上角显示自己的身份。
2. 在“Agent 目录”找到合适的 Agent，查看说明、服务状态和可用入口。
3. 标准模板的 Web 对话使用你的个人 Relay Key。按当前部署提供的个人设置入口接入；
   若界面尚未开放该入口，请联系平台团队，不要把 Key 粘贴到消息框。
4. 打开“对话”，新建会话。需要接续工作时，在工作台的最近个人对话中打开原会话。
5. 选择当前 Agent 提供的模型和推理强度，写明任务、输入范围和希望得到的结果。
6. 发送消息。确认时间线出现已提交或处理反馈；等待回复，必要时展开执行详情。
7. 回复完成后检查结果和文件。涉及外部写入时，继续核对目标系统与 Connection 调用记录。

建议第一次使用一个只读任务，例如：

> 阅读我提供的需求，列出需要澄清的问题，并给出实施步骤。先不要修改文件或调用外部写操作。

**完成标志：** 消息具有明确终态，结果可查看。模型声称“成功”不能替代工具和目标系统的实际回执。

## 03 · 员工、Owner 与管理员

| 身份 | 可以做什么 | 权限边界 |
| --- | --- | --- |
| 员工 | 使用获准 Agent、提交申请、看自己的历史与审计 | 不能读取其他人的会话 |
| Agent Owner | 配置共同 Owner、范围、模型、渠道与生命周期 | Owner 不自动获得其他人的内容或 Connection |
| 系统管理员 | 审批、停用、重试创建、处理 Owner、查看治理审计 | 管理身份不等于所有任务正文可读 |
| 应用及责任人 | 通过独立应用身份调用获准 API | 应用不继承责任人的个人权限 |

Owner 权限相同，Agent 必须保留至少一名有效 Owner。管理权限与使用范围是不同判断；
看得到管理入口不保证某项操作有权执行。平台与 Connection 的管理员职责也不互相继承。

## 04 · 创建与审批

**入口：** 我的管理 → 创建申请。Web 创建需要系统管理员审批。

1. 填写名称和用途，说明谁会使用以及预期处理的工作。
2. 选择标准模板或部署批准的自定义镜像来源。模板必须显示已就绪才能申请。
3. 设置共同 Owner 与可用范围。优先采用完成任务所需的最小人员或组织范围。
4. 标准模板填写 Agent 默认 Relay Key、模型清单和默认项；凭证只进入专用配置表单。
5. 按模板要求填写环境变量或 Secret，核对配置后提交。
6. 在“我的 Agent”或申请详情查看状态。待审批时可修改或撤回；撤回后再次申请需新建申请。
7. 被驳回时查看原因，修改原申请并重新提交。审批通过后等待创建，不要把批准视为服务已就绪。

| 状态 | 你的下一步 |
| --- | --- |
| 待审批 | 等待、修改或撤回 |
| 已驳回 | 阅读原因并修改原申请 |
| 已撤回 | 查看记录，需要时重新申请 |
| 创建中 | 查看进度，等待服务就绪 |
| 创建失败 | Owner 或管理员查看原因后重试 |
| 可用 | 查看实时服务状态，进入对话或配置 |
| 已停止 | Owner 可以启动或重启 |
| 已停用 | 联系管理员；Owner 不能自行恢复 |

创建审批用于控制资源。获准后的模型、范围、渠道调整及正常生命周期操作不要求重新审批。
不要依赖邮件或企微审批通知；主动在 Web 查看处理结果。

## 05 · 选择模板与自定义 Agent

规范定义 Codex、Claude、OpenCode、Pi 四种标准模板，分别面向编程、知识工作、开源编程和
可扩展工作流。**实际可申请项以目录的真实就绪状态为准**，名称出现不等于运行、模型、
浏览器工具或 Connection 已通过验收。

标准模板由平台团队升级，Owner 不锁定旧版本。升级时不能使用的会话显示“更新中”，
保留历史；失败先恢复旧版本，无法恢复时显示暂时不可用。

自定义 Agent 使用部署批准的 OCI 镜像，并固定不可变 Digest，Tag 更新不会自动改变已有实例。
创建时选择以下一种入口归属：

- **平台交互入口：** 镜像须通过 ACP 核心兼容性验证，使用平台身份和对话；模型、附件和文件以验证结果为准。
- **自有交互入口：** 镜像负责自身会话和体验，Owner 明确身份责任，平台只发布获准入口。

通过 Builder 构建镜像属于单独的受控链路；缺少实际构建、推送和运行证据时不能宣称发布完成。
普通员工不需要自行配置 Registry 拉取凭证。不要提供外部未获准镜像或以本地运行成功代替准入验证。

## 06 · 对话、历史与执行详情

**入口：** 工作区 → 对话，或 Agent 详情 → 对话。

- 新任务需要独立上下文时新建会话；延续先前工作时打开原会话。
- 同一 Agent 可供多人使用，每个平台会话有独立 Sandbox、工作区和记忆。不同会话不共享上下文。
- 离开页面不会自动取消已提交任务。返回原会话查看状态，避免再次提交同一外部操作。
- “停止”表示提出停止请求；等待停止确认，不把按钮点击当作所有工具已终止。
- 忙碌时按页面提示等待或重试。支持补充指令时可补充，投递失败必须明确处理，不能假定已执行。
- 结果未知或恢复待核实时，先回读原操作；不要用新会话重放可能已产生外部效果的任务。
- 执行详情展示实际可获得的模型、工具调用及结果摘要，不展示模型内部思考原文。

Agent 不可用时，历史保持只读。单个会话恢复失败不表示整个 Agent 失败：查看“会话不可用”
说明，需要时明确新建会话。平台会话不支持分享、分支、用户删除或导出。

已安装 Skill 与 Runtime 原生命令只在实际提供时展示。选择后检查参数再发送；目录出现
或模型自报加载不代表 Skill 已实际执行。Skill 不增加文件、模型或 Connection 权限。

若部署开放 Skill Hub，先在个人库或市场选择获准的固定版本并安装，再由 Owner 为 Agent
配置对应版本与使用权限。等待同步完成、实际挂载确认后，在对话输入框搜索并选择 Skill，
填写参数后提交。共享发布须经管理员审核；个人安装不自动授予其他用户或 Agent 使用权。
升级由用户明确选择，新版本不会自动替换已固定版本。当前 Web 尚无 Hub 入口时，不能把
Runtime 中已安装的 Skill 目录当作完整发布、审核和安装生命周期。

## 07 · 模型与 Relay Key

Owner 配置标准模板的模型清单、默认模型和推理强度；使用者只从该清单中选择。
同一会话可以切换，选择从下一条消息生效，不改变旧消息。

| 调用渠道 | 使用的 Relay Key | 处理方法 |
| --- | --- | --- |
| Web 与托管企微 | 实际发送者的个人 Key | 本人在个人设置中接入、替换或撤销 |
| Platform API 与评测 | Agent 默认 Key | Owner 检查默认 Key 与模型权限 |
| 自有交互入口 | 镜像自己的配置 | 按自定义 Agent 的说明处理 |

个人 Key 缺失、过期、额度不足或无权使用模型时，本次任务失败；平台不会自动改用 Owner
或 Agent 默认 Key。接入 Key 只证明其可用性，不代表已核实 Relay 账号归属，费用按 Relay
中该 Key 的实际归属计算。

自定义平台入口若提供经验证的模型选择，则从 Runtime 当前选项选择；选项失效时重新选择，
不能假定平台会替你切换。凭证不进入普通消息、截图或工单。

## 08 · Owner 配置与生命周期

**入口：** 我的 Agent → 对应 Agent → 配置与生命周期。

1. 修改前查看 Agent 状态及当前配置，确认自己仍有 Owner 权限。
2. 调整共同 Owner 和可用范围，保留有效 Owner，检查受影响用户。
3. 标准模板修改模型清单和默认项；自定义 Agent 按镜像要求配置环境变量。
4. 普通值可以回显；Secret 只显示是否已配置，更新时提供替换值，不尝试回读旧值。
5. 标准模板只允许开放的配置键；自定义镜像可配置自有键，但不能覆盖 `AGENT_INFRA_*` 保留键。
6. 保存后查看返回结果和实际服务状态。变更失败时按原因修正，不以本地输入框内容判断生效。

**停止**释放计算资源，保留配置、渠道、历史与数据。**重启**恢复服务并保留会话归属；
创建失败时使用专门重试入口。**停用**由管理员撤销运行资格，Owner 不能恢复。M1 不支持删除 Agent。

自定义镜像升级必须由 Owner 明确选择版本，候选验证失败时保留或恢复旧版本。降级前评估
Runtime 自有数据兼容性；平台不保证自动快照或业务数据库迁移回滚。

## 09 · 附件与企微渠道

上传前查看当前 Agent 与渠道支持的类型和大小限制。文件随当前主体和会话隔离，
不能把别人的附件地址或结果引用当作自己的访问权限。

Owner 在部署开放的渠道配置入口绑定企微智能机器人或自建应用；扫码授权和手动配置以
实际部署支持为准。取消、超时和验证失败均不算连接成功，确认“已连接”后再发测试消息。

- 发送者必须能映射到公司身份，并在 Agent 可用范围内；没有身份或权限时不执行任务。
- 标准模板要求发送者已接入个人 Relay Key，企微使用 Owner 设置的默认模型和推理强度。
- Web、智能机器人与自建应用的会话不合并。同一群内不同发送者使用各自平台会话。
- 群成员能看到群内消息和回复；Agent 可用范围只能限制触发者，不能隐藏已发到群里的内容。
- 替换凭证、解绑或变更回调前确认对已有连接的影响。平台不自动覆盖正式应用的回调。

## 10 · 连接外部账号并授权

**入口：** 团队提供的独立 Connection HTTPS 控制台。Platform 的 Connection 链接只是入口，
不是代登录或代授权。

1. 登录 Connection，确认是自己的公司身份。
2. 查看当前发布的 Provider 和 Action，阅读用途、参数、scope 与外部效果类型。
3. 对获准 Provider 连接外部账号，核对 OAuth 页面和回调后显示的账号。
4. 选择需要授权的 Consumer、安装实例及适用 Actor，确认具体 Connection 与精确 Action 版本。
5. 阅读授权预览，再在 Connection 中确认。连接账号成功不会自动创建调用授权。
6. 在客户端重新发现可用能力，用只读操作核对账号和返回结果。
7. 不再使用时撤销对应授权或安装实例；断开账号与撤销客户端授权是不同操作。

当前正式 M1 首个 GitHub Pilot 仅包括当前用户、个人仓库列表、创建 PR 三项能力，
并限制到专用账号和一个获准 private 仓库。其他 Provider、任意仓库、删除或合并操作不属于
该 Pilot。历史部署可能有更大的目录，不能以旧目录证明当前新规范已验收。

Owner 不替你选外部账号，也不能替你授权。多人使用同一 Agent 时，每个人仍须独立完成
Connection 的身份与授权；缺少凭据时不能回退到 Owner、其他用户或平台服务身份。

## 11 · Codex 与其他客户端接入

只有当前部署批准并完成兼容性验证的客户端版本可以接入。先向平台团队获取 endpoint、
注册方式和适配文档；配置一个 URL 不代表完整鉴权链路可用。

Codex 的最小 endpoint 配置形式如下，域名使用团队提供的实际 Connection 地址：

```toml
[mcp_servers.connection]
url = "https://connection.example.com/mcp"
```

受支持的 OAuth 流程可由客户端启动，例如 Codex 的 `codex mcp login connection`。
浏览器完成 Connection 登录、实例登记和授权后，再进行只读验证。失败时按部署说明检查
客户端版本、回调及凭据状态，不以自报用户或实例标识绕过认证。

Connection 使用标准 MCP 与 OAuth PKCE；PAT 只适用于经过注册批准的 Consumer，绑定
明确主体及 token 实例。只有部署选用 sender-constrained profile 时才额外要求持有证明，
不要求所有客户端统一采用私有协议。不要将凭据跨主体、实例或 Agent 复用。
客户端调用凭据存入受控凭据存储，不进入模型上下文、消息、工具参数或日志。

Codex 专用说明与通用 Agent 的 SDK/MCP 接入说明应分别阅读；一个客户端验收成功不能证明
其他客户端或 SDK 已兼容。开发者按授权目录顺序发现能力、读取契约、执行并核对实际结果，
不要自报 Principal、ConsumerInstance、Actor 或目标账号来选择身份。

## 12 · 外部写入与结果未知

执行前确认目标、输入范围和操作效果。例如创建 PR，应确认仓库、源分支、目标分支和标题，
不把“先分析”当作发布授权。只调用当前账号、Action 版本和目标范围允许的操作。

WRITE 超时或断连后可能已经产生效果。看到 `UNCERTAIN`、结果未知或待核实时：

1. 保留原调用编号和任务编号。
2. 回读原调用及目标系统，例如检查 PR 是否已经存在。
3. 由有权限的人员完成对账；核实前不要更换幂等键、再次创建或用新会话重放。
4. 将实际外部结果与任务终态对应，不能把目标查询失败当作“没有产生效果”。

同一业务操作重试沿用原幂等语义。Connection 保存外部效果和调用权威，平台只保存自身
任务与受信采集的关联；“关联未核实”时不能用另一条真实调用来证明当前任务成功。

## 13 · 管理员审批与审计

**审批：** 系统管理 → 创建审批。检查申请目的、Owner、范围、镜像/模板和资源规格；
批准后等待创建与验证，驳回必须填写可操作的原因。创建失败时先读失败原因再重试。

**治理：** 系统管理 → Agent 管理。停用前确认影响；Owner 离职或禁用后补充有效 Owner，
不会自动把离职者的个人 Connection 或会话转交其他人。

**审计：** 平台审计核对谁、何时、对哪个对象执行了什么、授权和实际结果。自己的任务使用
“我的执行审计”。Connection 外部调用在 Connection 中独立查询，两侧分别授权。
审计记录不复制消息正文、附件、模型内部思考或凭证值。

应用 API、凭证材料授权、评测数据授权与真实运行结果须按对应正式文档和实际入口核验。
应用责任人不自动获得应用任务内容，管理员也不能通过审计绕过内容权限。

## 14 · 常见问题与处理顺序

| 现象 | 先检查什么 | 下一步 |
| --- | --- | --- |
| 无法登录 | 公司账号、部署登录入口、认证服务提示 | 重试或联系身份管理员 |
| 看不到 Agent | 当前身份和 Agent 可用范围 | 请 Owner 核对范围，不改 URL 绕过 |
| 模板不可申请 | 模板就绪原因 | 等待平台团队完成验证 |
| 申请一直待审批 | 原申请状态 | 联系管理员，不重复创建相同申请 |
| 没有回复 | 原消息是否受理、任务状态、服务是否更新中 | 返回原会话或查看执行详情 |
| 个人 Relay Key 错误 | Key 可用性、额度及所选模型权限 | 本人替换 Key 或选择获准模型 |
| 历史只读 | Agent 停止/停用、更新或会话恢复失败 | 处理对应服务或会话状态 |
| Connection 没有能力 | 是否登录正确实例、已连接账号、已确认精确 Action | 在独立 Connection 完成授权 |
| OAuth 登录失败 | 客户端兼容性、实例登记、回调与凭据状态 | 重新走获准登录流程，保留脱敏错误 |
| 外部写入超时 | 原调用状态及目标系统实际结果 | 先对账，禁止盲目重复提交 |
| 群聊无法触发 | 发送者身份、范围、个人 Key、渠道状态 | 修正对应条件后测试 |
| 附件上传失败 | 支持类型、大小及会话权限 | 使用符合限制的文件 |

提交问题时提供时间、页面/Agent 标识、任务或调用编号、错误码、复现步骤和脱敏截图。
不要发送密码、Cookie、PAT、API Key、完整私密会话或外部账号凭证。

## 15 · 开发、运维与权威文档

开发运行使用仓库固定的 Node.js 24 和 `package.json` 中的 pnpm 版本。先安装锁定依赖并构建 Web 的共享契约：

```bash
pnpm install --frozen-lockfile
pnpm --filter @agent-infra/contracts build
pnpm dev:web
```

该命令只启动 Platform Web，不会自动准备数据库、身份、API、Worker 或 Runtime。完整本地
运行按部署说明准备依赖与配置；未配置认证时业务页面可能无法使用，静态指南仍可阅读。
启动 Web 后通过导航进入“使用指南”（`/help`），可搜索、选择章节或下载完整说明书。
章节链接例如 `/help?chapter=10`；静态说明可在登录前阅读，业务操作仍要求登录。
