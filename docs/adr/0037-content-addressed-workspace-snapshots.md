# ADR-0037：自定义 Agent 使用内容寻址的只读工作区快照

## 状态

方案与 M1.1 范围已确认；本文待产品与工程最终评审。当前 M1 行为不变。

## 背景

自定义 Agent 的源码与预置依赖只能随镜像交付，独立改变代码或环境也需要重建镜像。
直接引用用户已有 PVC/PV 会引入外部卷所有权、跨 Agent 访问、保留/删除及任意 Kubernetes
权限问题，并且 RWO 卷不能作为多个 Session 的共享工作区。

## 决策

采用平台托管的内容寻址目录归档，作为自定义 Agent 获准镜像之外的只读输入。
产品规则只在 [PRD 5.8](../prd/PRD-agent-platform-M1.md#58-工作区快照m11)维护；
契约、事务、物化、安全与验收规则只在
[工程 Spec 10.15](../architecture/SPEC-agent-infra-M1-engineering-architecture.md#1015-工作区快照m11)维护。

上传主体拥有快照，digest 不是权限。Platform DB 固定配置版本的引用，对象存储保存不可变
归档；平台 materializer 负责验证与物化。单镜像自有入口使用 Agent 专属缓存，平台会话与
多服务各 Pod 使用独立临时卷；所有业务容器只读挂载。业务可写数据仍由原工作区/应用管理。

Builder/CI 复用既有 Connection 授权和构建流程，平台只消费经过接收校验的产物与可信血缘，
不新增源码构建服务或 Connection 授权权威。多服务继续遵循
[ADR-0027](../architecture/ADR-0027-multi-service-standard-resource-description.md)的资源白名单；
快照是平台注入项，不允许用户声明 init container、任意 PVC/PV、hostPath、SA/RBAC 或特权容器。

## 取舍

源码和环境可独立于镜像更新，配置修订能够固定、审计并回滚输入；代价是上传、验证、
对象存储和冷启动物化成本。只读输入不支持安装时原地改写依赖，应用须把可写数据放入
原有工作区；环境可移植性由产物与运行镜像共同决定。明确拒绝损坏或无法物化的快照，
不会以镜像旧内容冒充成功。

保留当前镜像输入是 M1 的既有行为；M1.1 不采用任意卷引用、PVC 快照恢复、OCI artifact
或可写覆盖层。有限的凭据检测不能证明源码安全，真实部署、业务输出与隔离需要独立验收。
