# ADR-0029：标准模板模型清单来自默认 Key 的 `/models`

## 状态

已采纳。产品决定由 Owner 在 [#3115](https://github.com/AgoraIO-Extensions/agent-infra/issues/3115) 中确认，实现归属同一 Issue。取代 [ADR-0026](0026-show-model-reasoning-as-conversation-content.md) 决策 7 中“随镜像追加模型条目”和 `codexModelProfiles` 的部分。

## 背景

[平台 PRD §8.1](../prd/PRD-agent-platform-M1.md#81-owner-配置) 要求 Owner 从默认 Key 在 Relay 可见、且与模板兼容的模型中选择。实现中，`/models` 返回结果之后还要经过三份写死的清单：

- 部署 Catalog 的 `allowedModels`，部署文档要求逐个列出模型；
- 私有 API 配置里从 Runtime 镜像离线生成的 `codexModelProfiles`；
- Runtime 镜像里的 Codex 模型目录：内置列表加上仓库中的追加条目，就绪检查按 `model/list` 判定。

结果是每接入一个模型，都要改仓库、重建镜像、改部署配置。复制来的追加条目还带上了别的模型的身份声明：DeepSeek 条目沿用 GPT-5.6 的系统指令，回答时自称 GPT-5（#3113）。推理档位取端点和模板的交集，不区分模型。

固定 Codex 0.153 对目录中不存在的模型会使用默认回退元数据和默认系统指令，并不要求逐个模型登记。平台的模型传输入口始终按已保存的档位写入 `reasoning.effort`。

## 决策

1. **清单来源。** 候选只来自 Agent 默认 Key 调用 Relay `/models` 返回的 id。部署 Catalog 的 `allowedModels` 只作为可选限制，值为 `null` 时不限制；平台不再要求逐个登记模型。
2. **推理档位。** 平台固定提供 `low`、`medium`、`high`，适用于每个模型，不按模型、端点或模板登记。部署 Catalog 中已有的档位字段兼容读取，但不再收窄候选，也不再作为准入条件。
3. **保存时真实验证。** 申请提交、API 创建、配置更新和默认 Key 替换时，对新增的（模型，档位）组合，用默认 Key 按模板协议各发一次极小的真实请求，标准 Codex 模板走 Responses。
   - 未变化的组合不重复验证；替换 Key 时验证全部组合。
   - 验证失败即拒绝保存，原因区分以下情况：Key 无效、模型或档位不兼容、Relay 暂时不可用。
   - 请求只发往部署批准的 Relay 端点，沿用 `/models` 的 TLS、禁止重定向、超时和大小限制；请求与响应正文不进入日志、审计或错误。
   - 由此产生的少量费用计入该 Key。
4. **Runtime 使用 Driver 默认值。** Runtime 镜像的 Codex 模型目录只保留固定 release 的内置条目，删除平台追加的条目。
   - 就绪检查不再要求每个选项都出现在 `model/list` 中。
   - 命中内置条目的模型沿用上游元数据，其余模型使用 Codex 默认回退元数据和默认系统指令。
   - 平台不为单个模型生成、复制或登记元数据；需要调整时，由 Owner 通过模板开放的环境变量配置。
5. **部署配置兼容。** 私有配置中已有的 `codexModelProfiles` 和模板级 `reasoningLevels` 仍可读取但会被忽略，API 与 Worker 照常启动。删除这些配置不需要同时发布。
6. **已保存配置。** 已有 Agent 的已保存组合（包括固定档位之外的档位）继续可用，Runtime 和 Worker 不因本决策重新判定。新增组合只能使用固定档位，且须通过验证。

## 风险与边界

- 未内置模型使用默认元数据，上下文窗口、截断等参数不一定贴合具体模型，效果可能不如专门调过的条目。这是 Owner 接受的代价，效果按 PRD 第 15 节评估。
- 真实验证只能证明保存时可用，不能保证随后每次调用成功。Relay 后续下线模型或改变行为时，按调用失败处理。
- 不在本决策内：新增 Owner 可配置的调优环境变量键、非 Codex 标准模板的无 Key 模型配置，以及自定义 Agent 的模型配置。

## 备选方案

- **继续在镜像里追加模型条目：** 每个模型都要改仓库、重建镜像并重新生成部署配置，复制条目还会带入错误的身份声明。拒绝。
- **按模型维护部署级元数据表：** 仍然是写死的登记，只是挪了位置。拒绝。
- **只用 `/models` 可见性、不做真实验证：** 协议不兼容的模型（例如走 Responses 返回 400 的模型）会被保存，直到使用者调用失败才暴露。拒绝。
