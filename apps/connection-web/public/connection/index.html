C Connection 使用指南 登录控制台

Codex MCP

将 Connection 安装到 Codex

通过一个受控入口使用 GitHub、Jira、Confluence 等外部服务。Connection 保管账号凭证，Codex 只获得你明确授权的 Action。

1

添加 MCP 服务

在本机终端执行：

codex mcp add connection --url __CONNECTION_ORIGIN__/mcp
2

登录 Connection

继续执行，随后在浏览器中完成公司账号登录：

启用入口保护时，先完成公司 OAuth 登录，回跳后自动完成入口校验（未自动跳转时等待两秒，使用出现的“完成公司登录”按钮），再使用 LDAP 登录 Connection。账号归属和权限以 LDAP 账号为准，已有连接与授权保留；客户端不需要 公司入口 Cookie 或额外 apiKey。

页面校验或会话失效时，按提示重新打开授权入口并再次登录确认，本次提交不会自动重放。内置浏览器若清除或隔离 Cookie，请复制恢复入口到系统浏览器继续，不要复制密码、Cookie 或 Token。

codex mcp login connection --scopes mcp --oauth-client-registration dcr

安装不会自动授予外部账号权限

连接器默认关闭公司审批，可直接连接自己的账号；只有管理员开启审批的连接器需要先申请并获得有效资格。关闭审批不替代外部账号验证或 Codex 的 Action 授权。

登录后，请在 Connection 控制台连接所需的 Provider，并明确批准 Codex 可以使用的账号和 Action。不要把 LDAP 密码、Connection Token 或 Provider Credential 粘贴到聊天或 Codex 配置中。

打开 Connection 控制台

读取 GitHub Actions 日志需单独选择并授权 github.get_workflow_job_logs。原始日志会进入已授权客户端或模型上下文；分页和错误恢复见GitHub 接入帮助。

遇到 429 请按 Retry-After 等待后重试，不要循环提交。完整管理 API 文档需 Connection 登录；MCP 发现仍使用公开 metadata，不要求公司入口 Cookie。

Jenkins Pipeline 管理

以实际发布目录为准，支持普通 Pipeline 的发现、配置读取、创建与更新、启用/禁用、参数发现和取消排队。CI 与 Release 分别授权，新增能力需本人确认；Jenkins 原生权限仍须满足。

先读配置和预览，更新携带配置摘要；摘要预检不是原子 CAS，避免并发编辑。创建不自动构建，禁用不停止已有 Build。写入结果未知时先核验，不自动重试；不在脚本或 Git 地址中放入密码。
